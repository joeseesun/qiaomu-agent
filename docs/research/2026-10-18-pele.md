# Pele chat diagram adoption — 2026-10-18

## Decision and sources

Use pinned Pele 1.6.0 for flowchart, sequence and mindmap in completed chat Mermaid fences. Preserve the existing host renderer for other types and rendering incompatibilities. Source/edge/output-limit errors stop rather than bypassing limits. Markdown and native notes still use Obsidian APIs; original fenced source is unchanged in persisted messages and copy/append.

- https://github.com/obsidianmd/pele at `458322a5b8abb1ae57ddf127c32017ab9fb14a92`; npm 1.6.0, MIT with included Lucide ISC notice; zero runtime/React peer dependencies.
- https://pele.run/api, https://pele.run/compatibility, https://pele.run/theming, https://pele.run/security.
- Reviewed current https://ui.shadcn.com/docs/ai-elements and its Message, Button and Collapsible patterns. They provide message/actions/disclosure composition, not a Mermaid layout engine. Keep existing adapted message components and native details/button controls; no React 19 migration or Streamdown replacement of vault-aware MarkdownRenderer.

## Integration

Pele's own mount/zoom lifecycle supplies responsive layout, text measurement, resize/font handling, keyboard zoom and pan. A thin adapter maps chat semantic colors and fonts, sanitizes every SVG via the public Obsidian sanitizeHTMLToDom API, and disables links, images and custom icons. Limits: 20,000 source characters, 500 edges, 1,000,000 SVG characters; existing six-diagrams-per-response cap stays in place. Incomplete fences remain text until complete. No network or vault write is needed to display a diagram.

The package is unmodified. Its native overlay controls are disabled; chat controls use Lucide with host accessible names/tooltips, consistent with this project's explicit AGENTS.md requirement and existing icon buttons. Language follows the existing Chinese-default/English-host helper convention. CSS is limited to the plugin. Color changes preserve the mounted SVG; font changes refresh measurements. Cleanup destroys zoom, resize/font observation and local theme observers.

## Known compatibility boundary

Pele has its own layout and does not implement arbitrary HTML labels, Mermaid themeVariables or external diagram plugins. A successful render can differ from the native note's diagram. Saving preserves Mermaid source, not this visual layout. CSS variables require inline SVG, so host sanitization and disabled links/images replace the previous inert-image boundary only for the selected types. Host fallback remains inert.

The current plugin already reuses host Mermaid, so this change adds bundle size. No 500x performance claim is made. Node fixtures establish generation, not browser appearance; release acceptance separately records real Obsidian rendering, themes, widths, zoom, safety, lifecycle and upgrade evidence.
